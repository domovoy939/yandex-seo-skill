# Техника под Яндекс

## Редиректы и зеркала
- Одна версия сайта: `https://` + без www (или с www — главное одна). Все остальные варианты отдают **301 одним прыжком** на главное зеркало. Цепочка `http → https → без www → со слешем` из трёх прыжков — ошибка: делай правило, которое сразу ведёт на финальный адрес.
- Директива `Host` в robots.txt устарела (Яндекс перестал её учитывать в 2018 году). Главное зеркало задаётся 301-редиректом и, при смене домена, «Переездом сайта» в Вебмастере.
- Единый формат слеша на конце URL, второй вариант — 301.

## Ответы сервера
- Несуществующая страница отдаёт **404** (или 410), а не 200 с главной (мягкая 404). У одностраничных приложений это частая ошибка: сервер на любой адрес отдаёт index.html. Решение — отдавать index только для известных маршрутов, остальное — 404 со своей страницей и `noindex`.
- Важные страницы — 200 без редиректов.
- HTML не кэшировать надолго (`Cache-Control: no-cache`), статику с хешем в имени — на год.

## robots.txt
- Не закрывай CSS/JS — робот должен рендерить страницу.
- `Clean-param` (поддерживает Яндекс) — склеивает адреса с UTM и служебными параметрами: `Clean-param: utm_source&utm_medium&utm_campaign&utm_content&utm_term`.
- Строка `Sitemap:` с полным адресом.
- Отдельный блок `User-agent: Yandex` нужен, только если правила для Яндекса отличаются.

## sitemap.xml
- Только канонические страницы, отдающие 200, без noindex.
- `lastmod` — реальная дата изменения, не «сегодня» для всех.
- Добавить в Вебмастер, обновлять при деплое.

## Мета и разметка
- `title` до ~60–65 символов, уникальный, с основным запросом и городом для локальных услуг.
- `description` до ~160 символов, с оффером и ценой «от».
- Один `h1`, по смыслу совпадает с title.
- `canonical` на каждой странице, на саму себя (или на основную версию).
- Schema.org JSON-LD: Organization / LocalBusiness (NAP как в карточке), Service с ценами, BreadcrumbList, FAQPage. Яндекс поддерживает Schema.org и Open Graph.
- Open Graph: `og:title`, `og:description`, `og:image` 1200×630 — для превью в мессенджерах.

## Одностраничные приложения (React, Vue)
Яндекс умеет рендерить JS, но хуже и медленнее, чем Google. Проверь:
- в исходном HTML (до JS) есть текст и ссылки на разделы — лучше пререндер или SSR;
- после выполнения JS ссылки на разделы остаются настоящими `<a href>`, а не кнопками с обработчиком клика;
- у каждого раздела свой адрес, который открывается напрямую и отдаёт 200 со своим title.

## Скорость и мобильная версия
- Мобильная версия обязательна, viewport задан.
- Тяжёлые WebGL/видео на первом экране на телефоне — запускать после первой отрисовки или по взаимодействию, на слабых устройствах — статичная картинка.
- Шрифты — свои (woff2, кириллица), с `preload` и фолбэком с `size-adjust`, чтобы не прыгал заголовок (CLS).
- Изображения первого экрана — без `loading="lazy"`, с `fetchpriority="high"`, в WebP/AVIF под размер показа.

## IndexNow
Яндекс поддерживает IndexNow: после изменения страниц отправь список адресов — робот придёт быстрее.
1. Сгенерируй ключ (8–128 символов: латиница, цифры, дефис).
2. Положи файл `/<ключ>.txt` с содержимым = ключ в корень сайта.
3. После каждого деплоя — POST на `https://yandex.com/indexnow` (или общий `https://api.indexnow.org/indexnow`, он раздаёт всем участникам). Скрипт: `scripts/indexnow.py`.
