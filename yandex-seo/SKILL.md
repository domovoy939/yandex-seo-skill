# SEO под Яндекс

В России большую часть поиска даёт Яндекс, а большинство SEO-инструментов для агентов знают только Google. Этот скил закрывает Яндекс: от семантики в Вордстате до локальной выдачи в Картах.

## Главные отличия Яндекса от Google (держи в голове всегда)

1. **Регион решает.** Выдача по коммерческим запросам у Яндекса сильно зависит от региона пользователя. Сайту нужен назначенный регион (Вебмастер или карточка в Яндекс Бизнесе), иначе он плохо ранжируется по «услуга + город».
2. **Коммерческие факторы.** Для коммерческих запросов Яндекс оценивает, похож ли сайт на настоящий бизнес: цены, контакты, реквизиты, ассортимент, способы связи, доставка/оплата, отзывы. → `references/commercial-factors.md`
3. **Поведенческие факторы.** Клики из выдачи, возвраты в поиск и время на сайте весят больше, чем в Google. Первый экран должен сразу отвечать на запрос.
4. **Карты в выдаче.** По локальным запросам («веб-студия самара») сверху стоит блок Яндекс Карт. Без карточки в Яндекс Бизнесе сайт туда не попадёт. → `references/local.md`
5. **Своя семантика.** Частотность берётся только из Вордстата, у Google Keyword Planner другие цифры. Многие «очевидные» запросы ищут покупатели, а не заказчики. → `references/wordstat.md`
6. **IndexNow и Вебмастер вместо Search Console.** Переезд домена, регион, переобход, ИКС — всё в Яндекс Вебмастере. → `references/webmaster.md`
7. **Закон.** Метрика — это cookie и персональные данные: включать после согласия, нужна политика по 152-ФЗ и уведомление в РКН. → `references/ru-legal.md`

## Порядок работы

Работай по шагам и в конце каждого показывай результат, прежде чем идти дальше.

### Шаг 1. Техническая проверка (без доступа к кабинетам)
Запусти скрипт — он работает на стандартной библиотеке Python 3.9+, ничего ставить не нужно:
```bash
python3 scripts/yandex_tech_check.py https://example.ru
```
Он проверяет то, что важно Яндексу: цепочки редиректов (http/https, www, слеш — должен быть один прыжок 301), честную 404, robots.txt (Clean-param, устаревший Host, доступ YandexBot), sitemap, canonical, title/description по длине, viewport, подтверждение Вебмастера, Метрику и где она грузится, разметку Schema.org, ключ IndexNow и сигналы коммерческих факторов на главной (телефон, цены, ИНН/ОГРН, политика, контакты).

Добавь `--json`, если нужно сохранить результат. Скрипт не заменяет PageSpeed и проверку рендера — для одностраничных приложений (React/Vue) отдельно проверь, видит ли робот ссылки после выполнения JS (см. `references/technical.md`).

### Шаг 2. Семантика в Вордстате
Вордстат открывается только в браузере и иногда показывает капчу. Если у пользователя есть Claude в браузере — дай ему задание из `templates/browser-task-wordstat.md`. Если нет — попроси пользователя снять цифры по списку запросов.

Главное в этом шаге — **интент**. Для каждого кластера реши, кто ищет:
- **заказчик** («сайт для застройщика», «создание сайтов самара») — это наш спрос;
- **покупатель** («сайт жк», «интернет-магазин для бренда» → ищут конкретный ЖК или магазин) — это не наш спрос, хоть цифры и большие.
Подробности, операторы и как читать подзапросы → `references/wordstat.md`.

### Шаг 3. Разбор выдачи
По 5–10 главным запросам посмотри топ-10 Яндекса **в нужном регионе и без рекламы**: кто стоит (студии, агрегаторы, статьи, Карты, колдунщики), какие у них цены, офферы, блоки. Шаблон задания — `templates/browser-task-serp.md`, как читать — `references/serp.md`. Вывод шага: какой тип страницы ранжируется (посадочная, статья, каталог, карточка в Картах) — такую и делаем.

### Шаг 4. Коммерческие факторы и контент
Сверь сайт с чек-листом `references/commercial-factors.md`. Для каждой посадочной: один интент — одна страница, ответ на запрос на первом экране, цена «от» или калькулятор, реквизиты и контакты, кейсы с цифрами, FAQ.

### Шаг 5. Вебмастер, Метрика, IndexNow
По `references/webmaster.md`: подтверждение (DNS TXT или meta), sitemap, регион, переезд со старого домена (только после 301 с главной), переобход важных страниц, IndexNow после каждого деплоя:
```bash
python3 scripts/indexnow.py --host example.ru --key <ключ> --sitemap https://example.ru/sitemap.xml
```
Если кабинеты недоступны (сбой, нет доступа) — запиши шаги в план и не выдумывай статусы.

### Шаг 6. Локальная выдача
Если бизнес работает в городе — карточка в Яндекс Бизнесе (для онлайн-бизнеса без офиса — зона обслуживания, без домашнего адреса), 2ГИС (только с публичным адресом), отзывы. → `references/local.md`

### Шаг 7. План
Сведи всё в приоритеты:
- **P0** — то, из-за чего Яндекс не видит или не понимает сайт (нет индексации, ссылки только в JS, мягкие 404, цепочки редиректов, нет региона);
- **P1** — коммерческие факторы и скорость на телефоне;
- **P2** — мета-теги, разметка, IndexNow, мелочи;
- **Контент** — какие страницы и статьи делать по семантике и выдаче.

Для каждого пункта: что именно сделать в коде или в кабинете и как проверить.

## Правила честности
- Частотность — только из Вордстата, с указанием периода и региона. Нет данных — пиши «нет данных».
- Не проходи капчи за пользователя и не обходи защиту сервисов.
- Не обещай позиции и сроки выхода в топ.
- Не создавай фейковые отзывы, не накручивай поведенческие факторы — Яндекс за это пессимизирует, а это ещё и обман.
- Не публикуй и не регистрируй ничего от имени бизнеса без явного «да» владельца.
